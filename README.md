# Circuit / InductEx Project

This project automates key steps in the circuit design and verification workflow between **Custom Compiler**, **KLayout**, and **InductEx**.

### Main Purposes

#### 1. SPICE File Translation
- Parse SPICE netlists generated by Custom Compiler.
- Convert them into InductEx-compatible `.cir` circuit files.
- Process the `sol.txt` file generated by InductEx.
- Use extracted component values from `sol.txt` to generate an updated SPICE representation of the circuit.
- Automatically use the original Custom Compiler netlist when no `sol.txt` is available.
- Automatically generate and use `Netlist_from_sol.sp` when an InductEx `sol.txt` file is available.

#### 2. KLayout Automation
- Automatically add component names to the layout.
- Calculate and place the electrical ports required by InductEx.
- Reduce the amount of manual layout preparation required before extraction and simulation.
- Keep the current `.gds`, `.sp`, and `.cir` files together so it is clear which files belong to the current circuit.

#### 3. Web-Based Circuit Visualization
- Generate structured circuit data from Custom Compiler SPICE files.
- Automatically draw the circuit in a browser-based schematic interface.
- Make it easier to inspect components and nets.
- Trace unexpected InductEx results back to the corresponding schematic elements.

The main Python entry point is:

```text
main.py
```

The web interface is located at:

```text
UI/main_page.html
```

## 1. Create the Virtual Environment

Run these commands from the project root.

### Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

If your system uses `python` instead of `python3`:

```bash
python -m venv .venv
source .venv/bin/activate
```

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### Windows Command Prompt

```cmd
python -m venv .venv
.venv\Scripts\activate.bat
```

## 2. Install the Dependencies

After activating the virtual environment:

```bash
pip install -r requirements.txt
```

## 3. Run the Python Program

With the virtual environment activated:

```bash
python main.py
```

On some Linux systems, use:

```bash
python3 main.py
```

The program will ask you to select the circuit project to run.

### Running a Project

You can select the circuit project directly from the command line using either the long `--project` option or the short `-p` option.

```bash
python main.py --project splitter
```

or:

```bash
python main.py -p vfhalf
```

Replace `splitter` or `vfhalf` with the name of the project you want to run.

### Project File Organization

Each project has a dedicated `_Inductex` folder containing the files associated with the current circuit.

For example:

```text
Circuit_Projects/
└── Splitter/
    └── Splitter/
        ├── Previous_CIRs/
        │   ├── splitter.cir
        │   ├── splitter_V1.cir
        │   ├── splitter_V2.cir
        │   └── ...
        │
        ├── Splitter_Inductex/
        │   ├── Netlist.sp
        │   ├── Netlist_from_sol.sp
        │   ├── Layout.gds
        │   └── splitter_V3.cir
        │
        ├── sol.txt
        └── splitter.xi
```

The `_Inductex` folder is intended to contain the files that belong together for the current circuit:

- The latest original Custom Compiler `.sp` netlist.
- The latest `.gds` layout.
- The generated `Netlist_from_sol.sp` when extracted InductEx values are available.
- The latest generated `.cir` file.

Older `.cir` files are kept separately in `Previous_CIRs`.

### Automatic `.sp` and `.gds` Organization

When a project is first created, its Custom Compiler `.sp` and `.gds` files are placed in the project root.

For example:

```text
Circuit_Projects/
└── Splitter/
    └── Splitter/
        ├── Netlist.sp
        └── Layout.gds
```

When the project is executed for the first time, the program automatically moves these files into the corresponding `_Inductex` folder:

```text
Circuit_Projects/
└── Splitter/
    └── Splitter/
        └── Splitter_Inductex/
            ├── Netlist.sp
            └── Layout.gds
```

These files then become the files actually used by the program.

If Custom Compiler later exports a new `Netlist.sp` or `Layout.gds` into the project root, the next execution detects the new files and moves them into the `_Inductex` folder, replacing the previous versions.

For example, before running:

```text
Splitter/
├── Netlist.sp
├── Layout.gds
└── Splitter_Inductex/
    ├── Netlist.sp
    └── Layout.gds
```

After running:

```text
Splitter/
└── Splitter_Inductex/
    ├── Netlist.sp
    └── Layout.gds
```

If no new `.sp` or `.gds` file exists in the project root, the program continues using the versions already stored inside the `_Inductex` folder.

This allows updated files to be exported from Custom Compiler without manually reorganizing them.

### Running Without `sol.txt`

When no `sol.txt` exists, the program uses the original Custom Compiler netlist directly.

For example:

```text
Splitter_Inductex/
├── Netlist.sp
├── Layout.gds
└── splitter.cir
```

The workflow is:

```text
Netlist.sp
    ↓
Circuit parsing and KLayout processing
    ↓
splitter.cir
```

The first `.cir` therefore uses the values contained in the original Custom Compiler netlist.

### Running With `sol.txt`

After the generated `.cir` and `.xi` files are used with InductEx, InductEx produces a `sol.txt` containing the extracted component values.

The `sol.txt` file remains in the project root:

```text
Splitter/
├── Splitter_Inductex/
├── Previous_CIRs/
├── sol.txt
└── splitter.xi
```

When `sol.txt` exists, the next execution automatically combines the original Custom Compiler netlist with the extracted values from `sol.txt`.

The workflow becomes:

```text
Netlist.sp
    +
 sol.txt
    ↓
Netlist_from_sol.sp
    ↓
Circuit parsing and KLayout processing
    ↓
new .cir
```

The generated `Netlist_from_sol.sp` is stored inside the `_Inductex` folder:

```text
Splitter_Inductex/
├── Netlist.sp
├── Netlist_from_sol.sp
├── Layout.gds
└── splitter_V1.cir
```

`Netlist.sp` remains the original/latest Custom Compiler netlist.

`Netlist_from_sol.sp` contains the same circuit with supported component values updated using the InductEx extraction results and becomes the netlist used for that execution.

### Current and Previous `.cir` Files

Only the `.cir` generated by the current/latest execution remains inside the `_Inductex` folder.

For example:

```text
Splitter_Inductex/
├── Netlist.sp
├── Netlist_from_sol.sp
├── Layout.gds
└── splitter_V3.cir
```

Previous CIR files are automatically moved into:

```text
Previous_CIRs/
```

For example:

```text
Previous_CIRs/
├── splitter.cir
├── splitter_V1.cir
└── splitter_V2.cir
```

This keeps the `_Inductex` folder focused on the files currently being used while preserving all previous `.cir` versions.

After generation, the new `.cir` file is automatically opened so that it can be inspected or used directly with InductEx.

### The `.xi` File

Each execution creates a `.xi` file if one does not exist or updates the existing `.xi` file.

The `.xi` file remains in the project root.

For example:

```text
Circuit_Projects/
└── Splitter/
    └── Splitter/
        ├── Splitter_Inductex/
        ├── Previous_CIRs/
        ├── sol.txt
        └── splitter.xi
```

The `.xi` file is updated to reference the current:

- `.cir` file.
- `.gds` layout.
- Top-level cell name.

This ensures that the InductEx configuration always points to the current circuit files.

### Typical InductEx Iteration

A new project may initially look like this:

```text
MyProject/
├── Netlist.sp
└── Layout.gds
```

Run:

```bash
python main.py -p my_project
```

The program automatically reorganizes the files and generates the first CIR:

```text
MyProject/
├── MyProject_Inductex/
│   ├── Netlist.sp
│   ├── Layout.gds
│   └── MyCell.cir
│
├── Previous_CIRs/
└── MyCell.xi
```

Run InductEx using the generated `.xi` file.

After InductEx produces `sol.txt`:

```text
MyProject/
├── MyProject_Inductex/
│   ├── Netlist.sp
│   ├── Layout.gds
│   └── MyCell.cir
│
├── Previous_CIRs/
├── MyCell.xi
└── sol.txt
```

Run the Python program again:

```bash
python main.py -p my_project
```

The program uses `sol.txt` to generate `Netlist_from_sol.sp`, moves the previous CIR into `Previous_CIRs`, and generates the next CIR version:

```text
MyProject/
├── MyProject_Inductex/
│   ├── Netlist.sp
│   ├── Netlist_from_sol.sp
│   ├── Layout.gds
│   └── MyCell_V1.cir
│
├── Previous_CIRs/
│   └── MyCell.cir
│
├── MyCell.xi
└── sol.txt
```

The same process can then be repeated for additional InductEx iterations.

### Adding a New Project

To add a new circuit project, first create a new folder inside:

```text
Circuit_Projects/
```

Add the project's initial SPICE netlist (`.sp`) and layout file (`.gds`) inside this folder.

For example:

```text
Circuit_Projects/
└── MyProject/
    ├── Netlist.sp
    └── Layout.gds
```

Next, open:

```text
project_list.py
```

Add the new project to the `PROJECTS` dictionary by providing the paths where newly exported `.sp` and `.gds` files will initially appear.

For example:

```python
PROJECTS = {
    "multiplexer": {
        "netlist": "Circuit_Projects/MultiplexerAmeli/BasicCellsHomemade_MultiplexerAmeli.sp",
        "layout": "Circuit_Projects/MultiplexerAmeli/MultiplexerAmeli.custom_compiler.gds",
    },

    "ndrom_cells": {
        "netlist": "Circuit_Projects/NDROmCells/Netlist.sp",
        "layout": "Circuit_Projects/NDROmCells/BIG_Cellname.gds",
    },

    "ndrom_wires": {
        "netlist": "Circuit_Projects/NDROMWires/LayoutDone_NDROMDrivers.sp",
        "layout": "Circuit_Projects/NDROMWires/NDROMDrivers.custom_compiler.gds",
    },

    "splitter": {
        "netlist": "Circuit_Projects/Splitter/Splitter/Netlist.sp",
        "layout": "Circuit_Projects/Splitter/Splitter/Layout.gds",
    },

    "ndrom_drivers": {
        "netlist": "Circuit_Projects/NDROMDrivers/Netlist.sp",
        "layout": "Circuit_Projects/NDROMDrivers/NDROMDrivers.custom_compiler.gds",
    },

    "vfhalf": {
        "netlist": "Circuit_Projects/VFHalf/LayoutDone_VFHalf.sp",
        "layout": "Circuit_Projects/VFHalf/VFHalf.custom_compiler.gds",
    },

    "ndrom_drivers_old": {
        "netlist": "Circuit_Projects/NDROMDrivers 1 (1)/NDROMDrivers/LayoutDone_NDROMDrivers.sp",
        "layout": "Circuit_Projects/NDROMDrivers 1 (1)/NDROMDrivers/NDROMDrivers.custom_compiler.gds",
    },

    "my_project": {
        "netlist": "Circuit_Projects/MyProject/Netlist.sp",
        "layout": "Circuit_Projects/MyProject/Layout.gds",
    },
}
```

The dictionary key becomes the project name used from the command line.

For example:

```bash
python main.py --project my_project
```

or:

```bash
python main.py -p my_project
```

The configured paths represent the locations where newly exported Custom Compiler files are expected to appear.

When the project runs:

- If a new `.sp` file exists at the configured path, it is moved into the project's `_Inductex` folder and becomes the current original netlist.
- If a new `.gds` file exists at the configured path, it is moved into the project's `_Inductex` folder and becomes the current layout.
- If no new file exists at the configured location, the version already stored inside `_Inductex` is used.

Make sure the paths in `project_list.py` exactly match the filenames and initial locations of the Custom Compiler files.

## 4. Start the Local Web Server

Open a second terminal in the project root and activate the virtual environment.

Start the server on port `8080`:

```bash
python -m http.server 8080
```

On Linux, if `python` is not available:

```bash
python3 -m http.server 8080
```

Then open this address in your browser:

```text
http://localhost:8080/UI/main_page.html
```

## 5. Use Another Port

You can replace `8080` with another available port.

For example:

```bash
python -m http.server 8000
```

Then open:

```text
http://localhost:8000/UI/main_page.html
```

Another example:

```bash
python -m http.server 3000
```

Then open:

```text
http://localhost:3000/UI/main_page.html
```
